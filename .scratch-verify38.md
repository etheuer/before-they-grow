A process death after media movement but before journal advancement leaves a valid final that is treated as an orphan and deleted, defeating recovery. This violates DoD 1–2 and AC 1–2/8.
- **Major — inventory is not fully fail-closed.** Unknown files inside `layout-v1` are discovered only after SQLite has opened/possibly created and schema-initialized the database. Unknown files in older layout directories are ignored entirely. Existing older layouts are accepted but never migrated. This violates AC 5–6 and the “never recreate” requirement.
- **Major — filesystem migration is incomplete scaffolding.** `switchTo()` is a no-op; copying handles only recognized media, not catalog/reference state, and migration resumes after cleanup and database bootstrap. It does not satisfy transactional reference switching or preservation on failure (AC 7–8, DoD 5).
- **Major — tests miss key seams.** No adapter-level failure injection covers copy/validate/switch, corrupt journals, pending-save ordering, older-layout unknowns, or media backup-control failure. Several fakes only record calls and do not model actual filesystem/database effects.

No material unrelated scope creep; hard-delete and checksum UI are explicitly required. The migration abstraction is added but unfinished.
